# Release notes for pkpdbib 0.2.0
![pkpdbib](./docs/images/favicon/pkpdbib-100x100-300dpi.png)

We are pleased to release pkpdbib 0.2.0. The release modernizes the package and its infrastructure in line with sbmlutils, sbmlsim and pymetadata, reduces the footprint of the installation and fixes several bugs of the PDF retrieval and the Zotero utilities.

## Features

- PDF retrieval (`pkpdbib.scihub_tools`):
  - `scihub_pdfs` has the options `--out` for the directory of the PDFs and `--scihub-url` for the Sci-Hub domain.
  - `scihub_pdfs` and `scihub_pdfs_from_dois` return and report the citation keys for which no PDF could be retrieved, so a partial run is visible and can be repeated.
  - `scihub_pdfs_command` accepts the arguments as a list, so the command line interface can be called from python.
- Zotero libraries (`pkpdbib.zotero_tools`):
  - `create_tag_table` returns a `polars` data frame with one boolean column per selected tag, and fills the `pubmed` column with the PubMed id of the `extra` field of the item.
  - `pmid_from_extra` reads the PubMed id from the `extra` field of a Zotero item.
  - `examples/zotero_tags.py` creates the tag table of a group library, the API key is read from the environment variable `ZOTERO_API_KEY`.
- Documentation at [matthiaskoenig.github.io/pkpdbib](https://matthiaskoenig.github.io/pkpdbib) with a user guide for the PDF retrieval and the Zotero libraries, an API reference generated from the docstrings and the files for agents (`llms.txt`, `llms-full.txt` and the markdown of every page).

## Fixes

- `get_items` without a limit returns all items of the library instead of only the first page of the Zotero API.
- `create_tag_table` handles items without a DOI and selects a tag only once if several prefixes match.
- `dois_from_json` skips items without a DOI or citation key and reads the export as UTF-8 on every platform.
- `get_logger` adds its handler only once, repeated calls no longer duplicate the output.
- Importing `pkpdbib` no longer creates a `results/` directory next to the installation and no longer installs the rich pretty printer globally.

## Breaking changes

- Python >= 3.13 is required, python 3.13 to 3.15 are supported.
- Smaller installation: the core package only depends on `rich` and `scidownl`. The Zotero utilities need the optional `zotero` extra, i.e., `pip install "pkpdbib[zotero]"`, which adds `pyzotero` and `polars`.
- `pandas` was replaced by `polars`: `create_tag_table` returns a `polars.DataFrame`.
- `pkpdbib.RESOURCES_DIR`, `pkpdbib.RESULTS_DIR`, `pkpdbib.BASE_PATH`, `pkpdbib.program_name`, the `pkpdbib.projects` package and the `aliskiren.csv` resource were removed; the glucose example is now `examples/zotero_tags.py`.

## Infrastructure

- Packaging with `pyproject.toml` and hatchling instead of `setup.py`/`setup.cfg`; development with uv and a committed `uv.lock`; `bump-my-version` instead of `bump2version`; `README.md` instead of `README.rst`.
- Linting and formatting with ruff, type checking with ty (warnings are errors), both as pre-commit hooks and as required checks.
- Tests no longer access the network, the download of scidownl and the Zotero client are replaced by fakes. They run against python 3.13 to 3.15 on Linux, against python 3.15 on macOS and Windows, and against the lower bounds of the dependencies (`lowest`).
- GitHub workflows `CI-CD`, `ruff`, `ty` and `documentation`, with least privilege permissions and every action pinned to a commit SHA; dependabot updates the actions, `uv.lock` and the pre-commit hooks.
- Releases are built in a job without write permissions and published to PyPI by trusted publishing with attestations; the GitHub release is created from the release notes and `main` is fast-forwarded to the release.
- Repository rulesets in `.github/rulesets/`, applied with `.github/rulesets/apply.sh`.
- Documentation with Zensical and mkdocstrings, published to GitHub Pages from `develop`.
- `CITATION.cff` and updated Zenodo metadata (`.zenodo.json`).
